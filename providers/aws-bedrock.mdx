title: "AWS Bedrock provider configuration"
description: "Configure AWS Bedrock in Promptfoo to evaluate Claude, Llama, Nova, and Mistral models using standard AWS credential chains and managed infrastructure."
---

The `bedrock` provider lets you run evals against models hosted on Amazon Bedrock. It supports Bedrock model IDs directly, including regional IDs and cross-region inference profiles.

## Setup

### 1. Install the AWS SDK

```bash
npm install @aws-sdk/client-bedrock-runtime
```

### 2. Configure AWS credentials

The SDK reads credentials from standard AWS locations in order:

- IAM role (EC2, ECS, Lambda)
- `~/.aws/credentials` file
- `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` environment variables

```bash
export AWS_ACCESS_KEY_ID=AKIA...
export AWS_SECRET_ACCESS_KEY=...
export AWS_REGION=us-east-1
```

### 3. Enable model access

Request access to the models you need in the [AWS Console](https://console.aws.amazon.com/bedrock/home#/model-access). Anthropic models may require a one-time use-case submission.

## Provider string format

The provider string is `bedrock:` followed by the Bedrock model ID:

```yaml
providers:
  # Anthropic Claude (cross-region inference profile)
  - bedrock:us.anthropic.claude-opus-4-7-v1:0
  - bedrock:us.anthropic.claude-sonnet-4-6-v1:0

  # Meta Llama
  - bedrock:us.meta.llama3-3-70b-instruct-v1:0

  # Amazon Nova
  - bedrock:us.amazon.nova-pro-v1:0
  - bedrock:us.amazon.nova-lite-v1:0

  # Mistral
  - bedrock:mistral.mistral-large-2402-v1:0
```

<Note>
Use the [AWS model IDs documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/model-ids.html) or run `aws bedrock list-foundation-models` for current model IDs and regional availability.
</Note>

## Basic configuration

```yaml title="promptfooconfig.yaml"
providers:
  - id: bedrock:us.anthropic.claude-opus-4-6-v1:0
    config:
      region: us-east-1
      max_tokens: 2048
      temperature: 0.7
```

## Inline credentials

For testing or CI environments where you can't rely on the credential chain:

```yaml
providers:
  - id: bedrock:us.anthropic.claude-opus-4-6-v1:0
    config:
      accessKeyId: AKIA...
      secretAccessKey: ...
      region: us-east-1
```

## Application inference profiles

Inference profiles let you route requests to multiple regions via a single ARN. Set `inferenceModelType` to tell Promptfoo which model family is behind the profile:

```yaml
providers:
  - id: bedrock:arn:aws:bedrock:us-east-1:123456789012:application-inference-profile/my-profile
    config:
      inferenceModelType: claude
      region: us-east-1
      max_tokens: 1024
```

Supported `inferenceModelType` values: `claude`, `nova`, `nova2`, `llama`, `llama2`, `llama3`, `llama3.1`, `llama3.2`, `llama3.3`, `llama4`, `mistral`, `cohere`, `ai21`, `titan`, `deepseek`, `openai`, `qwen`.

## Comparing models

```yaml title="promptfooconfig.yaml"
providers:
  - id: bedrock:us.anthropic.claude-opus-4-6-v1:0
    config:
      region: us-east-1
      max_tokens: 1024

  - id: bedrock:us.meta.llama3-3-70b-instruct-v1:0
    config:
      region: us-east-1
      max_tokens: 1024

  - id: bedrock:us.amazon.nova-pro-v1:0
    config:
      region: us-east-1
      max_tokens: 1024
```

## Configuration reference

| Parameter | Environment variable | Description |
|---|---|---|
| `region` | `AWS_REGION` or `AWS_DEFAULT_REGION` | AWS region (e.g. `us-east-1`) |
| `accessKeyId` | `AWS_ACCESS_KEY_ID` | AWS access key ID |
| `secretAccessKey` | `AWS_SECRET_ACCESS_KEY` | AWS secret access key |
| `sessionToken` | `AWS_SESSION_TOKEN` | Temporary session token |
| `max_tokens` | — | Maximum tokens to generate |
| `temperature` | — | Output randomness |
| `top_p` | — | Nucleus sampling parameter |
| `inferenceModelType` | — | Model family for inference profile ARNs |
| `guardrailIdentifier` | — | Bedrock Guardrails identifier |
| `guardrailVersion` | — | Bedrock Guardrails version |
| `inputCost` | — | Override input token cost estimate |
| `outputCost` | — | Override output token cost estimate |
