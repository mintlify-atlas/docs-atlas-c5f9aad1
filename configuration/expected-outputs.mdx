title: "Assertion types for LLM output validation"
description: "Validate LLM outputs with assertions: equals, contains, regex, javascript, python, llm-rubric, factuality, is-json, similar, cost, and latency."
---

Assertions define conditions that LLM outputs must meet. Add an `assert` array to any test case to automatically check outputs and compute a pass/fail score. Assertions are optional — you can always review outputs manually in the web UI — but they unlock automated accuracy tracking across runs.

```yaml
tests:
  - vars:
      question: 'What is the capital of France?'
    assert:
      - type: contains
        value: 'Paris'
      - type: latency
        threshold: 3000
```

<Tip>
  Every assertion type can be negated with a `not-` prefix. For example, `not-contains`, `not-regex`, or `not-is-json`.
</Tip>

## Assertion properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `type` | string | Yes | Assertion type (see below) |
| `value` | string \| array \| object | No | Expected value or criteria |
| `threshold` | number | No | Numeric threshold for score-based types |
| `weight` | number | No | Relative importance of this assertion. Defaults to 1 |
| `metric` | string | No | Label for aggregating results in the web UI |
| `provider` | string | No | Override provider for model-graded assertions |

## Deterministic assertions

These run programmatic checks on the raw LLM output with no AI calls needed.

### equals

Passes if the output exactly matches the expected value.

```yaml
assert:
  - type: equals
    value: 'The expected output'
```

Also supports JSON matching:

```yaml
assert:
  - type: equals
    value: { 'key': 'value' }
```

### contains

Passes if the output contains the specified substring.

```yaml
assert:
  - type: contains
    value: 'Paris'
```

Use `icontains` for case-insensitive matching. Use `contains-all` or `contains-any` to check for multiple substrings:

```yaml
assert:
  - type: contains-all
    value:
      - 'introduction'
      - 'conclusion'
      - 'summary'
```

### starts-with

Passes if the output begins with the specified string.

```yaml
assert:
  - type: starts-with
    value: 'Yes'
```

### regex

Passes if the output matches the regular expression.

```yaml
assert:
  - type: regex
    value: "\\d{4}-\\d{2}-\\d{2}"  # Matches a date like 2024-01-15
```

### is-json / contains-json

`is-json` passes if the entire output is valid JSON. `contains-json` passes if valid JSON appears anywhere in the output.

Both support optional JSON schema validation:

```yaml
assert:
  - type: is-json
    value:
      type: object
      required:
        - latitude
        - longitude
      properties:
        latitude:
          type: number
          minimum: -90
          maximum: 90
        longitude:
          type: number
          minimum: -180
          maximum: 180
```

Load large schemas from a file:

```yaml
assert:
  - type: contains-json
    value: file://./schemas/response_schema.json
```

### javascript

Run arbitrary JavaScript to validate the output. The variable `output` contains the LLM response. Return `true`/`false`, a score (number), or a `GradingResult` object.

```yaml
assert:
  - type: javascript
    value: "output.toLowerCase().includes('bonjour')"
```

With a threshold:

```yaml
assert:
  - type: javascript
    value: Math.log(output.length) * 10
    threshold: 0.5
```

Multiline with structured result:

```yaml
assert:
  - type: javascript
    value: |
      const words = output.trim().split(/\s+/);
      return {
        pass: words.length >= 10 && words.length <= 100,
        score: Math.min(words.length / 100, 1),
        reason: `Output has ${words.length} words`,
      };
```

Load from an external file:

```yaml
assert:
  - type: javascript
    value: file://assertions/check_output.js
```

### python

Same as `javascript` but runs a Python expression. Return `bool`, `float`, or a dict with `pass`/`score`/`reason`.

```yaml
assert:
  - type: python
    value: output[5:10] == 'Hello'
```

Multiline:

```yaml
assert:
  - type: python
    value: |
      if len(output) < 10:
          return {'pass': False, 'score': 0, 'reason': 'Too short'}
      return {'pass': True, 'score': 1}
```

Load from a file:

```yaml
assert:
  - type: python
    value: file://assertions/validate.py
```

### latency

Passes if the LLM response arrives within the specified number of milliseconds.

```yaml
assert:
  - type: latency
    threshold: 5000  # 5 seconds
```

<Note>
  `latency` requires caching to be disabled. Run with `promptfoo eval --no-cache`.
</Note>

### cost

Passes if the inference cost is below the threshold (in USD).

```yaml
assert:
  - type: cost
    threshold: 0.001  # $0.001
```

Cost tracking is currently supported for OpenAI GPT models and custom providers that return cost metadata.

## Model-graded assertions

These use an LLM to grade outputs based on criteria you specify.

### llm-rubric

Uses an LLM judge to evaluate whether the output meets a free-form rubric.

```yaml
assert:
  - type: llm-rubric
    value: 'Response is helpful, professional, and under 200 words'
```

By default, promptfoo uses OpenAI GPT to grade. Override the grading provider:

```yaml
assert:
  - type: llm-rubric
    value: 'Does not describe itself as an AI'
    provider: anthropic:messages:claude-sonnet-4-6
```

### factuality

Checks whether the LLM output is factually consistent with a reference statement, using OpenAI's factuality eval methodology.

```yaml
assert:
  - type: factuality
    value: 'Paris is the capital of France and has a population of about 2 million'
```

### similar

Computes embedding-based cosine similarity between the output and a reference string. Passes if similarity exceeds the threshold.

```yaml
assert:
  - type: similar
    value: 'was geht'
    threshold: 0.6
```

Accepts multiple reference strings — passes if the output is similar to any one of them:

```yaml
assert:
  - type: similar
    value:
      - 'Hello there'
      - 'Hi there'
      - 'Greetings'
    threshold: 0.8
```

By default, embeddings are computed via OpenAI `text-embedding-3-large`.

## Threshold-based assertions

### Test-level threshold

Set a `threshold` on the test case itself to define a minimum combined score for the test to pass:

```yaml
tests:
  - vars:
      input: 'Hello'
    threshold: 0.5
    assert:
      - type: equals
        value: 'Hello world'
        weight: 2
      - type: contains
        value: 'world'
        weight: 1
```

If `equals` fails but `contains` passes, the combined weighted score is `1/3 ≈ 0.33`. Because `0.33 < 0.5`, the test fails. Lowering the threshold to `0.2` would make it pass.

### Weighted assertions

Use `weight` to control the relative importance of each assertion:

```yaml
assert:
  - type: equals
    value: 'Hello world'
    weight: 2    # Counts double
  - type: contains
    value: 'world'
    weight: 1
```

### Assertion sets

Group assertions together with a shared threshold:

```yaml
assert:
  - type: assert-set
    threshold: 0.5  # At least 50% of sub-assertions must pass
    assert:
      - type: cost
        threshold: 0.001
      - type: latency
        threshold: 2000
```

## Named metrics

Tag assertions with a `metric` label to aggregate results in the web UI:

```yaml
assert:
  - type: equals
    value: 'Yarr'
    metric: Tone
  - type: icontains
    value: 'grub'
    metric: Tone
  - type: is-json
    metric: Consistency
```

## Loading assertion values from files

The `value` field supports `file://` references:

```yaml
assert:
  - type: contains
    value: file://expected_output.txt
  - type: javascript
    value: file://assertions/custom_check.js
```

## All assertion types

<AccordionGroup>
  <Accordion title="Deterministic types">
    | Type | Passes when... |
    |------|----------------|
    | `equals` | Output matches exactly |
    | `contains` | Output contains substring |
    | `icontains` | Output contains substring (case-insensitive) |
    | `contains-all` | Output contains all listed substrings |
    | `contains-any` | Output contains at least one listed substring |
    | `starts-with` | Output starts with string |
    | `regex` | Output matches regex pattern |
    | `is-json` | Output is valid JSON |
    | `contains-json` | Output contains valid JSON |
    | `is-xml` | Output is valid XML |
    | `contains-xml` | Output contains valid XML |
    | `is-html` | Output is valid HTML |
    | `contains-html` | Output contains HTML content |
    | `is-sql` | Output is valid SQL |
    | `contains-sql` | Output contains valid SQL |
    | `is-refusal` | Output is a refusal to answer |
    | `javascript` | JavaScript function returns truthy/score |
    | `python` | Python expression returns truthy/score |
    | `latency` | Response time is below threshold (ms) |
    | `cost` | Inference cost is below threshold (USD) |
    | `rouge-n` | ROUGE-N recall score above threshold |
    | `bleu` | BLEU precision score above threshold |
    | `levenshtein` | Edit distance below threshold |
    | `webhook` | Webhook endpoint returns `{pass: true}` |
  </Accordion>

  <Accordion title="Model-graded types">
    | Type | Method |
    |------|--------|
    | `llm-rubric` | LLM judges output against free-form criteria |
    | `factuality` | LLM checks factual consistency with reference |
    | `similar` | Embedding cosine similarity above threshold |
    | `answer-relevance` | LLM checks relevance to original query |
    | `context-faithfulness` | LLM verifies output uses provided context |
    | `context-relevance` | LLM checks context relevance to query |
    | `model-graded-closedqa` | Closed QA grading from OpenAI evals |
    | `g-eval` | Chain-of-thought evaluation with custom criteria |
    | `classifier` | HuggingFace classifier returns expected class |
  </Accordion>
</AccordionGroup>
